# Bitacora - 2026-07-30

## Objetivo del dia

Completar la Fase 2 del plan de elevacion: separar los permisos del Director de Carrera y Vicerrectorado, y evitar que los datos de una carrera puedan ser consultados o modificados desde otra.

## Que se hizo

- Se reemplazo el campo tecnico `is_admin` por el rol explicito `director_carrera` o `vicerrectorado`.
- La base de datos valida que solo existan esos dos roles, que cada Director tenga una carrera y que Vicerrectorado no tenga una carrera asignada.
- Se migraron los usuarios existentes de forma segura. La migracion se detiene si encuentra datos que no cumplen las nuevas reglas.
- Se agregaron middleware y policies para separar rutas de Director y Vicerrectorado.
- Las acciones que reciben carreras, grupos, designaciones o revisiones ahora verifican la pertenencia antes de leer o modificar informacion.
- Un Director ya no puede cambiar una designacion aprobada ni usar el formulario para aprobarla.
- Las pantallas de Vicerrectorado solo admiten revisiones pendientes; los borradores permanecen privados para su Director.
- Se actualizaron factories, seeders, navegacion y pruebas al nuevo modelo de roles.

## Verificacion

- La migracion `2026_07_30_150000_replace_is_admin_with_roles` se aplico en PostgreSQL local.
- `php artisan test`, `vendor/bin/pint --test` y `composer audit --locked` finalizaron correctamente.
- Las pruebas cubren roles invalidos, reglas de carrera obligatoria, URLs y payloads de otra carrera, borradores no enviados y acceso exclusivo de Vicerrectorado.
