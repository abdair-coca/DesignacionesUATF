# Bitacora - 2026-07-30 - Fase 3

## Objetivo del dia

Reemplazar el concepto de envio mutable por borradores y versiones que conserven una evidencia historica completa.

## Que se hizo

- Se agregaron propuestas separadas de las designaciones heredadas, con un borrador unico por carrera, gestion y periodo.
- El Director gestiona las asignaciones del borrador por grupo, sin usar el CRUD individual antiguo.
- Solo la gestion marcada como actual permite crear, editar o enviar borradores.
- Cada envio crea una version numerada y una copia independiente de los datos del docente, materia, grupo, carrera, gestion y periodo.
- La base de datos bloquea la edicion y eliminacion de snapshots de versiones enviadas.
- Retirar una version pendiente conserva el historial, registra un evento y vuelve a habilitar el borrador. Un reenvio genera un numero de version nuevo.
- La navegacion principal del Director ahora abre Propuestas de Designacion.

## Verificacion

- Las pruebas cubren borrador unico, gestion actual, snapshots inmutables, cambios posteriores de catalogos, retiro por el Director remitente, reenvio secuencial y aislamiento entre carreras.
- La migracion se aplico en PostgreSQL local y en el esquema de pruebas.
